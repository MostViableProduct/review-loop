# P2: per-review Codex effort without writing `~/.codex`

Date: 2026-09-28. Codex CLI 0.158.0. Companion plugin `openai-codex/codex` 1.0.6.

## Verdict and decision

`P2=fail mechanism=none` for the engine's path. `P2.efforts=none,minimal,low,medium,high,xhigh`. `decision=display-only`.

- The engine calls `adversarial-review --wait --json` (`plugin/engine/lib/pin.mjs:254`). That path has no per-invocation effort mechanism: `--effort` is parsed as focus text and the run exits 0.
- `task --effort` does reach Codex, as the `effort` field of the app-server `turn/start` request (`codex-companion.mjs:490`, `lib/codex.mjs:1140`). Two `task --effort low` runs wrote session logs carrying `"effort":"low"` and `"reasoning_effort":"low"` while `~/.codex/config.toml` stayed byte-identical and its default is `high`.
- The author decided on 2026-09-28 that effort is display-only in v1 (AC-6 amended). Reviews stay on `adversarial-review`. Task 10 sets `EFFORT_ARGS = () => []`. Do not inject `--effort` into the review command: it would land in the focus text.
- The final `effortInLog=true` for `task` came from an offline re-check of the two logs written by the runs, made after the finder fix. It is not the script's own run output; the script printed `sessionLog:null` on both runs because of the finder bug below.

## Step 1: how effort reaches Codex (companion 1.0.6, `scripts/`)

- `codex-companion.mjs:82` usage lists `--effort <none|minimal|low|medium|high|xhigh>` on `task` only.
- `codex-companion.mjs:764` `handleTask` declares `valueOptions: ["model","effort",...]`; `:774` runs `normalizeReasoningEffort` (`:114-124`, set at `:71`).
- `codex-companion.mjs:490` `executeTaskRun` passes `effort` to `runAppServerTurn`; `lib/codex.mjs:1140` sends it as the `effort` field of the app-server `turn/start` request. It is a turn parameter: not a `-c` override, not an env var.
- `adversarial-review`: `handleReviewCommand` (`codex-companion.mjs:712-716`) declares `valueOptions: ["base","scope","model","cwd"]`, so `--effort` is not a known option. `lib/args.mjs` pushes unknown `--flags` into positionals, so `--effort low` is silently appended to the focus text instead of being rejected (exit 0). `runAppServerTurn` at `:411` is called without `effort`. The native `review` path (`:370`, `lib/codex.mjs:1026`) uses `review/start`, which also carries no effort.
- Env: the companion reads no effort env var. `CODEX_REASONING_EFFORT` is not consulted anywhere under `scripts/`.
- No `-c` override is forwarded by the companion.

## Runs (4 real Codex runs of the 4 allowed; run 4 was a re-run of `task` that only exposed a probe bug)

Each `configUnchanged` compares the sha256 of `~/.codex/config.toml` before and after. The config sets `model_reasoning_effort = "high"`, so a `low` match cannot come from the default.

```
{"mechanism":"flag","effort":"low","exit":0,"configUnchanged":true,"effortInLog":false,"sessionLog":null}
{"mechanism":"env","effort":"low","exit":0,"configUnchanged":true,"effortInLog":false,"sessionLog":null}
{"mechanism":"task","effort":"low","exit":0,"configUnchanged":true,"effortInLog":false,"sessionLog":null}   (probe bug, see below)
{"mechanism":"task","effort":"low","exit":0,"configUnchanged":true,"effortInLog":false,"sessionLog":null}   (probe bug, see below)
```

Probe bug: the original script located the session log with `find -newermt "@<epoch>"`. That works with the `find` shell function in this environment (bfs) but `/usr/bin/find` (BSD) rejects `@epoch` (`Can't parse date/time`), so `sessionLog` was null for both `task` runs even though logs existed. The script now walks the sessions dir in Node and compares mtimes. That fix was validated offline (no further Codex run) against the two logs the `task` runs wrote:

```
{"mechanism":"task","effort":"low","exit":0,"configUnchanged":true,"effortInLog":true,"sessionLog":"rollout-2026-09-28T21-42-44-01a0eb78-e7f1-7d02-87c5-7b47bf6faf91.jsonl"}
{"mechanism":"task","effort":"low","exit":0,"configUnchanged":true,"effortInLog":true,"sessionLog":"rollout-2026-09-28T21-43-18-01a0eb79-6af3-76c0-bbbf-deaa4cde8c1a.jsonl"}
```

Exit codes come from the recorded runs; `effortInLog` is from the offline regex check on those logs. Key names that carried the value, unchanged regex: `"effort"` and `"reasoning_effort"` (one occurrence each per log). `~/.codex/config.toml` sha256 before and after: `4719dc4f6c3dd7eafd9c630a3c98b3eb3d2e13ea8d23fdda97fae772c9f23a7f` (identical).

`flag` and `env` runs (adversarial-review) created no session log: that path opens an ephemeral thread, so no log to inspect. The effort loss is established by source (Step 1), not by log absence. `--effort` was not rejected: it became focus text.

## Allowed efforts

`none|minimal|low|medium|high|xhigh`, source: the companion's own validator (`codex-companion.mjs:71` and `:124`, "Use one of: none, minimal, low, medium, high, xhigh"). `codex --help` and `codex exec --help` do not enumerate values. Only `low` was exercised live.

## Notes for Task 10
