# P6: running-session detection

Command: `sh scripts/probes/p6-sessions.sh` (prints pid, kind and argv1 only; never full command lines)

`claude --version`: 2.1.284 (Claude Code)

## Policy: fail-safe (controller ruling R-P6, for Task 16)

Spec 6.2 refuses a settings.json write while any Claude Code process that could write it is running. Overcounting therefore only makes the refusal more cautious, and undercounting is unsafe. The classifier counts every `claude` process except pure helpers. Headless runs (`-p`/`--print`), stream-json children and `mcp serve` are COUNTED, because they can write settings.

## Finding: `pgrep -x claude` is unreliable

Process names show as the version (2.1.284), and helpers share the `claude` name. Measured: `pgrep -lx claude` returned helpers (2097 `--chrome-native-host`, 72761 `daemon`) plus one real session (28371) and missed real session 29623. Helpers seen via `ps -Ao pid,args`: `claude daemon`, `claude bg-pty-host`, `claude bg-spare`, `claude --chrome-native-host`.

## Classifier (`P6.cmd`)

`ps -Ao pid=,args= | awk "$CLASSIFY"`, where `$CLASSIFY` is defined in `scripts/probes/p6-sessions.sh`. Rules, applied to the full args string:

- skip a line only when its FIRST token's basename is exactly `awk`, `ps`, `grep` or `pgrep` (regex `/^([^ ]*\/)?(awk|ps|grep|pgrep)( |$)/`), which removes the script's own processes; an unanchored version wrongly dropped `/Users/x/Apps Folder/claude` (first token ends in `ps`), an undercount, so it was anchored;
- count a line matching `(^|/)claude( |$)` (works for paths containing spaces), or containing `/claude-code/cli.js` (a node-launched CLI);
- exclude only when the first argument after the executable is exactly `daemon`, `bg-pty-host`, `bg-spare` or `--chrome-native-host`.

No tty is required (a `bg-spare` helper has one, ttys001, and an IDE-hosted session may not).
